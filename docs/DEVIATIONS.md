# Deviations from the paper prototype

One line per difference, with the reason. Updated through Phase 7 (Final).

| Screen | Difference | Reason |
|---|---|---|
| All | Added **C6 Client Chat**, **A19 Messages Inbox & Thread**, **A20 Settings, Blocked Dates & Backups**, and **A21 Audit & System Logs** screens, plus a chat icon in the top bar. | Required by the build brief (professor's request for in-app messaging, owner-editable settings, and centralized audit/system log inspection). |
| C1 | The top bar has a chat icon instead of a menu icon, and there is a floating "Chat with us" button. | The client menu only had 3 items, which already sit in the bottom nav. Chat is the new contact channel. |
| A1 | Added a Show/Hide password button. | Easier to type on a phone. |
| A2 | The top bar shows the unread-messages badge on every admin screen. | Brief §7.2 (messaging). |
| More | "More" also lists Payments to verify, Messages, Crew & equipment, Clients & inquiries, Packages & services, Reports, Users & access, Settings & blocked dates, Audit & system logs, Change my password, and Log out, filtered by role/permission. | Gives a path to every screen that is not in the 5-item bottom nav. |
| Admin (desktop) | At ≥ 1024 px the bottom nav becomes a left sidebar. | Brief §5. The phone layout is unchanged. |
| C2 | The calendar is rendered by the server and every day is a link (full page load per tap) instead of an in-page widget. | Works without JavaScript and on slow phones. |
| C2 | Past dates are also greyed out and crossed out. | They cannot be booked, so they look the same as full dates. |
| C4 | The GCash QR shows a placeholder box until the owner uploads a QR image in A20 (`/files/gcash-qr`). | The reference documents give no QR image. |
| A4 | Added an **Archived** filter chip next to All · Pending · Confirmed · Balance due · Completed. | Needed so archived bookings can be found and restored (BR-8). |
| A5 | Added a **Down payment received now** direct booking option with on-the-spot Official Receipt (`OR-YYYY-NNNN`) issuance and project record creation. | Brief §7.2, §9.3 & real studio walk-in workflow where clients pay cash down payment immediately. |
| A6 | Added an **Internal Notes** tab with a `visible_to_crew` toggle, storing entries in `booking_notes` and logging to `booking_changes`. | Brief §7.2, §8.1. Keeps private studio instructions and crew logistics separate from client-visible messaging. |
| A7 | Added a duplicate GCash reference warning box with a required acknowledgement checkbox (`ack_duplicate`), and a waiting-requests banner when other pending bookings share the date. | Required by Brief §9.1 and §9.4 (Risk 3 fraud/duplicate guard). |
| A8 | When a booking has more than one verified payment (e.g. down payment + balance), the Official Receipt tab shows selector chips (`OR-2026-0006`, `OR-2026-0008`, …) so each payment's receipt can be printed individually. | Brief §7.2 and §9.3 require an official receipt for each verified payment. |
| A9 | Multi-event days without assigned crew show a prominent red shortage banner that dynamically clears to green upon assignment. Assigning crew to overlapping event hours is hard-blocked with an error. | Brief §7.2, §15 (Scenario T4). Prevents crew double-booking and gives clear visual alerts on unassigned events. |
| A10 / A11 | Studio logs RAW and EDITED directory paths and backup timestamps instead of uploading heavy media files. Cloud copy is tracked via a manual confirmation checkbox. | Business Rule BR-10 and shared hosting constraints (avoiding disk space/bandwidth exhaustion and external Drive API dependencies). |
| A11 | Releasing an overdue deliverable with an unpaid balance or uncompleted cloud copy requires an explicit confirmation checkbox override (`confirm_release_override`). Releasing a project with ₱0 balance automatically marks the booking status as `completed`. | Brief §7.2, §15 (Scenario T5), BR-10. Prevents accidental handover of unpaid work while allowing studio discretion. |
| A12 | Added 4 bilingual message templates (Tagalog and English) with alias support for placeholders (e.g. `[Client name]`, `[Event date]`, `[Balance]`) and dual dispatch modes (Copy for Messenger and Send in App Chat). | Brief §7.2, §12. Reflects real studio communication workflows in the Philippines (Facebook Messenger + in-app portal). |
| A13 | Rescheduling to an open date is free, updates schedule, and logs audit entries; cancellation enforces non-refundable deposit policy (verified down payments marked `is_forfeited = 1`, date capacity freed immediately, zero refund) and requires a confirmation checkbox. Completed bookings cannot be cancelled or rescheduled. | Brief §3.2, §9.5, §15 (Scenario T3). Protects studio revenue and date integrity while maintaining immutable audit history. |
| A14 | Added contact-channel filter chips (`Messenger · Call · Walk-in · Referral · Website · Archived`), inline **+ Add inquiry note**, and a dedicated client detail page (`/admin/clients/{id}`). | Makes walk-in and Messenger inquiry tracking fast on a mobile screen while preserving full booking and chat links per client. |
| A15 | Added an **Add-ons** management tab alongside **Photo & video** and **Other services**, plus per-package fixed down-payment overrides. | Brief §7.2 & §3.3 require editable add-on services and optional per-package down-payment overrides. |
| A16 | Added a **Daily / Monthly** toggle with a verified-receipts breakdown and a one-click CSV export (`/admin/reports/export.csv`). | Brief §7.2 (`A16`) requires both Daily/Monthly views, Print report, and Export CSV. |
| A17 | Creating a user with the `crew` role automatically creates a linked row in `crew_members`. | Ensures newly created crew logins can immediately be assigned on `A9` and view their schedule on `A18` without manual database linking. |
| A18 | Separated assigned events into a highlighted **Next assigned event** hero card (with call time, venue, inclusions, equipment, and crew-visible notes), **Later events**, and collapsible **Past events**. | Brief §7.2 (`A18`) & Scenario `T7` require crew to find their next event's call time and venue at a glance with zero financial data. |
| A20 | Grouped studio settings into 5 mobile-friendly tabs (`Studio & Rules`, `Blocked Dates`, `Terms & Policy`, `Templates & Replies`, `Backups`) with `.sql` download and manual cloud-copy confirmation. | Keeps the settings screen clean and scannable at 360 px while covering all settings in Brief §3.3, §7.2, and §9.6. |
| A21 | Added a 6-tab append-only log viewer (`Security & Audit`, `Booking History`, `Projects & Handover`, `Notifications`, `Backups`, `Errors & Rate Limits`) with filters, Print, and CSV export. | Brief §7.2 (`A21`), §9.8, and Scenario `T13` require surfacing all 6 log streams for Owner inspection and RA 10173 accountability. |
| PWA / Offline | Added `manifest.json`, `sw.js` (static shell caching only), and `offline.html` (zero private data cached). | Brief §5 & Scenario `T12` require home-screen installability and safe offline fallback on flaky cellular connections. |
| Architecture | Pure PHP 8.2 MVC architecture with PDO prepared statements and hand-rolled router/services; zero external framework or Composer dependencies. | Academic SAD project requirements and 100% shared hosting portability without CLI composer/npm access. |
| Image Processing | Upload validation uses PHP's built-in `finfo` (MIME detection) and `getimagesize` with optional GD re-encoding/thumbnails when `extension=gd` is enabled. | Default XAMPP on Windows and standard shared hosts often have `extension=gd` disabled in `php.ini`. |
| Time Authority | Studio operates under a configurable simulated date authority (`Clock::today()`) defaulting to `2026-12-12`. | Academic demonstration requirement: guarantees reproducible presentation of past/present/future events and overdue deliverables without manual clock tampering. |
