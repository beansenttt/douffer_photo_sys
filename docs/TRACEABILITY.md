# Douffer PhotoSys: Requirements Traceability Matrix

Maps every business rule (`BR-1` to `BR-10`), functional requirement category from the Preliminary Investigation Report / Business Case / Paper Prototype Guide, and non-functional requirement to its implemented **Screen ID**, **Route & Controller/Service**, and **Verification Test Case** (`PROMPT.md` §13.7).

---

## 1. Business Rules Traceability (`BR-1` to `BR-10`)

| Rule ID | Business Rule | Screen(s) | Route(s) & Code Implementation | Test Case(s) |
|---|---|---|---|---|
| **BR-1** | Reservation is locked **only** when down payment is received and verified; pending requests never count toward date capacity. | `C2`, `A3`, `A7` | `GET /availability`, `GET /admin/calendar`, `POST /admin/payments/{id}/verify` — `AvailabilityService::confirmedCount()`, `PaymentService::verify()` | `T1`, `T2`, `T8` (`tests/run.php`, `tests/e2e_booking.php`) |
| **BR-2** | Verified down payment is **non-refundable** on cancellation; recorded as **forfeited** (`is_forfeited = 1`). | `C4`, `A13`, `A6` | `POST /book/pay`, `POST /admin/bookings/{id}/change` — `BookingService::cancel()` | `T10` (`tests/run.php`, `tests/e2e_admin.php`) |
| **BR-3** | Rescheduling is **free** (`₱0.00`) if the new date passes the availability check. | `A13` | `POST /admin/bookings/{id}/change` — `BookingService::reschedule()` | `T3` (`tests/run.php`, `tests/e2e_admin.php`) |
| **BR-4** | Double-booking is impossible: server re-validates availability inside a transaction with row-level date lock (`date_locks`). | `C3`, `C4`, `A5`, `A7`, `A13` | `AvailabilityService::lockAndAssertOpen()` (`SELECT ... FOR UPDATE` on `date_locks`) | `T8` (`tests/run.php`, `tests/e2e_payments.php`) |
| **BR-5** | Clients pay by GCash with reference number + screenshot into a verification queue; never auto-verified. | `C4`, `C5`, `A7` | `POST /book/pay`, `POST /booking/{ref}/reupload`, `GET /admin/payments` — `BookingService::createPending()`, `PaymentService` | `T1`, `T2`, `T9` (`tests/e2e_booking.php`, `tests/e2e_payments.php`) |
| **BR-6** | Facebook Messenger & GCash stay as external channels, backed by internal records + built-in web chat (`C6`/`A19`) and `"Copy for Messenger"` actions (`A8`/`A12`/`A19`). | `C1`, `C6`, `A8`, `A12`, `A19` | `/chat*`, `/admin/messages*`, `/admin/bookings/{id}/messages/templates` — `MessageService`, `MessageTemplateService`, `DocumentService` | `T2`, `T11` (`tests/e2e_chat.php`, `tests/e2e_admin.php`) |
| **BR-7** | Project stages are **Booked → Covered → Editing → Ready → Released** with editing checklist (`editing`, `rendering`, `album layout`). | `A10`, `A11`, `C5` | `GET /admin/projects`, `POST /admin/projects/{id}/stage`, `POST /admin/projects/{id}/checklist` — `ProjectService` | `T5` (`tests/run.php`, `tests/e2e_admin.php`) |
| **BR-8** | Records are **archived (with restore), never hard-deleted** from the UI; logs are append-only. | `A4`, `A6`, `A14`, `A21` | `POST /admin/bookings/{id}/archive`, `POST /admin/clients/{id}/archive`, `GET /admin/logs` | `TC-14`, `TC-22`, `T13` (`tests/e2e_phase6.php`, `tests/e2e_phase7.php`) |
| **BR-9** | Customer data, contact details, and payment screenshots comply with **RA 10173 (Data Privacy Act of 2012)**. | `C3`, `C6`, `Privacy`, `A17`, `A18`, `A21` | `GET /privacy`, `GET /files/receipt/{id}`, `GET /files/chat/{id}` — `FileController`, `Guard`, `Audit` | `T1`, `T7`, `T11`, `T13` (`tests/e2e_booking.php`, `tests/e2e_chat.php`, `tests/e2e_phase7.php`) |
| **BR-10** | System logs where media files are kept (RAW/EDITED folder names, local backup, manual cloud copy) and handover details; never uploads heavy photo/video deliverables. | `A10`, `A11`, `A21` | `GET/POST /admin/projects/{id}/files`, `GET /admin/logs?tab=projects` — `ProjectService::saveFilesAndHandover()` | `T5` (`tests/e2e_admin.php`, `tests/e2e_phase6.php`) |
